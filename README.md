# 水浒维基 (shuihu-wiki)

> 让《水浒传》像代码一样：语法高亮、跳转、搜索、推理。

**线上站点：<https://shuihu-wiki.pages.dev>**（Cloudflare Pages；GitHub 推送即自动部署，链路见 `DEPLOY.md`）

## 使用说明

```bash
# 重建全站（改了 corpus/ 或 data/ 后执行一次）
~/.workbuddy/binaries/python/envs/default/bin/python scripts/render_site.py

# 本地预览
python3 -m http.server 8000 --directory site
# 浏览器打开 http://localhost:8000
```

- `scripts/fetch_corpus.py` —— 从维基文库抓取原文（已完成，无需重跑）
- `scripts/convert_t2s.py` / `validate_corpus.py` —— 繁转简 / 语料校验
- `scripts/parse_roster.py` —— 解析第71回石碣名单 → `data/heroes.json`
- `data/aliases_curated.json` —— 手工别名表，想加称呼直接改这里再重建
- `data/endings.json` —— 108 将结局（8 类），逐条据第110–120回核对，改完重建
- `data/places.json` —— 106 处地名（6 类别 × 实/存疑/虚 三档），每条必带「虚实判定依据」，改完重建
- `data/causal.json` —— 事件因果链：`chains` 10 条线索（有序事件名）+ `links` 54 条因果边（必须能说出「因为 A 所以 B」），改完重建
- `data/relations.json` —— 人物关系：`factions` 21 个山头/阵营（名单即集合，不拆成边）+ `links` 150 条关系边（8 类，每条带正文出处，159 位人物全覆盖），改完重建
- `scripts/check_links.py` —— 构建后体检：断链 + 锚点失效（应恒为 0）

当前站点：573 个静态页——首页 / 108将图鉴 / 108将结局 / 地名图志 / 因果链 / **人物关系** / 名场面长廊 / 搜索 / 404
+ 120 回×繁简双版阅读页 + 159 位人物词条页 + 106 个地名词条页 + 55 幕事件详情页。
159 位人物词条页各配一张 ego 关系图（一跳放射静态 SVG）；人物关系总览页配「百川归海图」（14 个山头汇入梁山）。全站除搜索页外零 JS。


## 一句话目标

用 AI 将《水浒传》（120回本，约90余万字）转化为可交互、可探索的知识图谱。
以「文本内世界」为准：用叙事时序（第几回）代替公元纪年，地名标虚实，人物有多重身份（姓名 / 绰号 / 星号）。

## 底本与版权

- **底本**：维基文库《[水滸傳 (120回本)](https://zh.wikisource.org/wiki/水滸傳_(120回本))》，明·施耐庵，公有领域
- **结构**：序 + 引首 + 第1–120回，子页面 URL 规律（`/第001回` … `/第120回`），适合程序化抓取
- **简繁**：底本为繁体，用 OpenCC 转简体，繁体原文保留备查
- **版权边界**：原文公有领域；本项目标注数据采用 CC BY-NC-SA 4.0；代码采用 MIT；引用须注明维基文库出处

## 路线图

### Phase 0 — 文本工程（先跑通）
- 抓取维基文库 序 + 引首 + 120 回 → 繁简双版本 Markdown
- 回目切分、段落编号
- ✅ 验收：本地能顺序读完全书，回目导航正确

### Phase 1 — MVP：阅读器 + 108 将
- 静态阅读页（回目导航 / 上一回 / 下一回）
- 108 将 + 主要人物（约 150 词条）别名表驱动的高亮与跳转
- 人物词条页：绰号 / 星号 / 座次 / 首登场回 / 结局 + 出场回目索引
- 全文搜索
- ✅ 验收：打开任意一回，好汉姓名可点击，词条页信息完整

### Phase 2 — 全量实体 + Wiki 网络
- 扩展至全部实体类型；每个实体生成词条页，页间互联
- ✅ 已完成：108将图鉴（含结局）· 名场面事件库（55 幕）· 其他人物（51 人）· **地名（106 处，虚实三档）**· **事件因果链（10 条线索 + 54 条因果边）**
- 待做：兵器器物 / 官职 / 诗词赞语

### Phase 3 — 关系与推理
- ✅ 已完成：**事件因果链**（`data/causal.json`，10 条线索 + 54 条因果边）、**人物关系**（`data/relations.json`，21 个山头阵营 + 150 条八类关系边，159 位人物全覆盖）、**人物关系图**（159 页 ego 图 + 总览页「百川归海图」，构建期静态 SVG 零 JS，design.md §5.20）
- 三者为关系类数据立了同一条范式：**先分清"数据能说什么、不能说什么"**，且**集合与边必须分家**（名单能说清的绝不拆成两两的边）；图只画两种能看的形态（个人一跳子图 / 集合归海图），不画全量关系网
- 待做：好汉落草路线图、文本内矛盾检测

### Phase 4 — 应用
- 行踪地图、二创素材引擎、与公众号排版工作流（md-wechat）联动

## 边界：明确不做什么

- ❌ 不做多版本汇校（70 / 100 / 120 回异文）——远期再说
- ❌ 不做历史考证（宋江是否实有其人等）——文本宇宙为准
- ❌ 不收录现代研究论著——可外链，不进库
- ❌ 不追求一次标注完美——AI 标注必有错，建立可迭代的修正流程
- ❌ 不做翻译 / 多语言——远期

## 已确认决策（2026-09-20）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 简繁体 | **简体为主 + 繁体对照** | 面向公众号简体读者；OpenCC 自动转换，原文可切换 |
| 技术路线 | **Python 渲染静态站**（AI 评估推荐，用户确认） | ① 与 shiji-kb 同构，方法论和脚本可直接借鉴；② 内容型站点 90% 是"读"，不需要前端框架；③ 对非技术背景最友好——改数据=改 Markdown，一条命令重新生成全站；④ 天然可部署 Cloudflare Pages，以后想上线零成本。Vue 应用适合强交互产品，对本项目属于过度工程；关系图等局部交互后期以嵌入组件方式补（即"静态内容+交互组件"的演进路径） |
| 特色功能优先级 | **108将图鉴（P0，进 MVP）→ 名场面事件库（Phase 2）→ 人物关系图（Phase 3）**；行踪地图降级为远期可选 | 用户多选确认 |
| 部署 | **GitHub 仓库 → Cloudflare Pages 自动部署**（`site/` 产物随仓库提交，CF 侧不跑构建） | 手工上传 dist 不可持续；内容站的本地渲染即唯一真源，产物必须过本地 `check_links.py` 体检才能上线。步骤见 `DEPLOY.md` |
